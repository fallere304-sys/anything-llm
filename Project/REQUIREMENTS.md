# REQUIREMENTS.md — 要件一覧

版: v0.1 / 2026-11-18。区分: **MUST**=必須(ゲート) / **SHOULD**=希望・全案が実装を目指す / **COULD**=希望・案ごとの重点 / **WONT**=初期版では実装しない。

## 1. 機能要件

### 1.1 CSV読み込み（MUST）

|---|---|---|
| FR-LOAD-01 | ファイル選択（ダイアログ＋ドラッグ&ドロップ(SHOULD)）と読み込み | GUI手動＋ヘッドレス |

| FR-LOAD-03 | RFC 4180準拠＋実務拡張: 引用符内のカンマ・改行・`""`エスケープ、改行コードCRLF/LF/CR混在の許容 | コーパス |
| FR-LOAD-04 | 区切り文字: 既定カンマ。タブ/セミコロンは手動指定(SHOULD) | |
| FR-LOAD-05 | ヘッダー行有無の指定（既定: 先頭行をヘッダー）。ヘッダーなしの場合は列番号を列名とする | |
| FR-LOAD-06 | ストリーミング処理により D-02（100万行/約500MB）を**ピークメモリ内で**完走。全行をメモリに保持しないこと（重複検出用のハッシュ集合を除く） | 性能テスト |
| FR-LOAD-07 | 読み込みエラー（存在しない/アクセス不可/他アプリがロック/空ファイル/バイナリ等）を**原因と対処**付きで平易に表示。クラッシュしない | 異常入力コーパス |
| FR-LOAD-08 | 進捗表示とキャンセル（2秒以内に停止）。処理中もUIが固まらない | 手動＋計測 |
| FR-LOAD-09 | 入力ファイルは**読み取り専用**で開く。書き込み・移動・削除・属性変更をしない | SHA-256/更新日時不変テスト |

### 1.2 データ品質検査（MUST）
各検出は共通の**ルールID**を持つ（評価の正解データとの突合キー）。

| ルールID | 検出内容 | 種別 | 既定 |
|---|---|---|---|
| E001 | 必須項目の欠損 | 決定的 | 必須指定列で有効 |
| E002 | NULL様トークン（`NULL`,`null`,`N/A`,`#N/A`,`NaN`,`None`,`-` 等。**設定可能**） | 決定的 | 有効 |
| E003 | 重複レコード（全列一致） | 決定的 | 有効 |
| E004 | 特定列（複合キー可）の重複 | 決定的 | 重複判定列指定時 |
| E005 | 数値列に数値でない値 | 決定的 | 型=数値の列で有効 |
| E006 | 日付形式の不統一（列内に複数形式が混在） | 決定的 | 型=日付の列で有効 |
| E007 | 日付として成立しない値（2/30、13月、0000-00-00 等） | 決定的 | 同上 |
| E008 | 数値の範囲外（最小/最大） | 決定的 | min/max指定時 |
| E009 | 不自然な文字列（制御文字・ゼロ幅文字・私用領域・機種依存/異体字(設定)・全半角混在(設定)） | 準決定的 | 制御文字/ゼロ幅のみ有効 |
| E010 | 前後の空白（半角・全角・タブ） | 決定的 | 有効 |
| E011 | 文字化け・不正文字コードの疑い（U+FFFD、典型mojibakeパターン、デコード不能バイト） | ヒューリスティック | 有効 |
| E012 | 列数の不一致（ヘッダーとの比較） | 決定的 | 有効 |
| E013 | ヘッダーの重複・空ヘッダー | 決定的 | 有効 |
| E014 | データ型の不一致（列の宣言型と値の型） | 決定的 | 型宣言列で有効（E005/E006/E007の上位。重複報告しない §3.4） |
| E015 | 項目間の論理矛盾（宣言的ルール） | 決定的 | ルール指定時 |
| E016 | 文字列の最大文字数超過（**コードポイント数ではなく Unicode 書記素/文字数の定義を §3.6 で固定**） | 決定的 | max_length指定時 |
| E017 | CSV構文エラー（閉じていない引用符、引用符外の不正な`"`） | 決定的 | 有効 |
| W101 | 統計的外れ値（IQR等） | ヒューリスティック | **既定OFF**、severity=warning |

| ID | 要件 |
|---|---|
| FR-CHK-01 | 上記の全ルールを実装する（W101はSHOULD） |
| FR-CHK-02 | 各検出は severity（error / warning）を持つ。決定的ルール=error、ヒューリスティック=warning（設定で変更可） |
| FR-CHK-03 | 検査対象列を選択可能（未選択列は検査しない。ただしE012/E013/E017は構造検査として常に実行） |
| FR-CHK-04 | 1ファイル検査は冪等であること（同一入力・同一ルールなら同一結果、順序も同一） |
| FR-CHK-05 | 全体の検出件数が極端に多い場合（例: 100万件超）も落ちない。**上限設定付きの打ち切り**を許し、打ち切りを明示（無言で捨てない） |

## 3. 検出セマンティクス（確定案・**ユーザー確認事項 U-1**）

評価の正解データを一意に決めるための取り決め。曖昧さがあると「誤検出/検出漏れ」の判定自体が成立しないため、先に固定する。

### 3.1 行番号
- `record_no`: ヘッダーを除くデータレコードの**1始まりの通し番号**（評価のキー）。
- `line_no`: そのレコードが始まる**物理行番号**（ヘッダー行=1。埋込改行があるとrecord_noと一致しない）。
- 画面・レポートには両方を表示する（利用者がExcelで探す際は、Excel行番号 = record_no + 1（ヘッダーありで埋込改行なしの場合）。ずれる可能性を画面に注記）。

### 3.2 空欄とNULL
- **E001**: 必須指定列で、空文字／空白のみ／NULL様トークン → 欠損。
- **E002**: 必須でない検査対象列に**NULL様トークン文字列**が書かれている場合のみ報告（プレースホルダ混入）。
- **必須でない列の空欄は異常としない**（誤検出防止）。列ごとに「空欄を異常とする」オプションで変更可能。
- E001対象のセルでE002は重複報告しない。

### 3.3 重複
- E003/E004は**2件目以降**の出現レコードを報告（1件目は基準として報告しない）。各検出に `first_seen_record_no` を付与。
- 比較は完全一致（正規化なし）が既定。前後空白・全半角を無視する正規化は列ごとのオプション。
- 大文字小文字は既定で区別。

### 3.4 型関連の重複報告の回避
- 1セル×1事象に1件を原則とする。型宣言列で数値でない値は **E005のみ**（E014は報告しない）。E014は「型宣言があり、E005/E006/E007で表現できない型（例: 論理型・列挙値）の不一致」に使う。→ これにより正解データの件数が一意になる。

### 3.5 発生率
- 異常の発生率 = **異常のあるレコード数 / 検査対象レコード数**（レコード単位）。併せて 検出件数(セル単位) と 種類別件数 も表示。**率の定義を画面に明記**。

### 3.6 文字数
- 最大文字数は**Unicodeコードポイント数**で数える（サロゲートペアを1文字）。結合文字・絵文字ZWJ列の扱いは「コードポイント数」と明記し、書記素単位は将来課題とする。[確定案]

### 3.7 日付
- 受理形式は明示指定のみ。曖昧な `dd/MM` と `MM/dd` は**推測しない**（指定形式のみ受理）。
- 混在判定(E006)は「列内で指定の複数形式のうち2種以上が使われている」場合。形式が1つ指定されていれば、それ以外の形式の値は E007 か E006 のどちらかに**一意に分類**（成立する日付で形式違い=E006、成立しない=E007）。

### 3.8 数値
- 受理: 半角数字、符号、小数点、（設定により）桁区切りカンマ・全角数字。`1e5` 等の指数表記・`NaN`/`Infinity` は既定で非数値。
- 範囲は閉区間既定（`min`以上`max`以下が正常）。
