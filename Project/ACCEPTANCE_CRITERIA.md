## 2. 検査精度基準

### 2.1 ゴールデンコーパス（`/Project/eval/corpus/`）
| 区分 | 内容 | 規模(最低) |
|---|---|---|
| 合成+注入 | 正常データに既知不正を注入。ルール別・組合せ・列数/行数違い | 各ルール20ケース以上、計200ケース以上 |
| クリーン | 不正を含まない正常データ（誤検出の測定用）。UTF-8/BOM/CP932、引用符内改行、全角文字、長文、多様な日付/数値を含む | 40ケース以上 |
| 手作りエッジ | CP932特殊文字(①㈱髙﨑)、BOM有無、CR/LF混在、埋込改行、ヘッダーなし、1列、1行、など | 50ケース以上 |
| 実務模擬 | 医療・介護事務風の**完全架空**データ（患者ID・日付・点数・区分等） | 10ケース以上 |
| 異常入力 | NFR-STAB-01の列挙事項 | 30ケース以上 |
| 大規模 | 100万行・約500MB（CIで生成。リポジトリには格納しない） | 2ケース |

### 2.2 合格基準
| 対象 | 指標 | 合格 | 目標 |
|---|---|---|---|
| 決定的ルール (E001,E002,E003,E004,E005,E006,E007,E008,E010,E012,E013,E014,E015,E016,E017) | precision / recall | **各100%**（G5） | — |

| W101 外れ値（有効化時） | precision / recall | 参考値として記録（合否対象外）。ただし既定OFFであること | — |
| クリーンコーパス | 誤検出件数（既定ルールセット使用時） | **0件** | — |
| 文字コード自動判別 | 正答率（1KB以上の対象ファイル） | ≥95% | ≥98% |
| 文字コード自動判別（誤判定時） | 手動指定で正しく読めること | 100% | — |
| 決定性 | 同一入力を3回実行し`findings.json`が(順序含め)完全一致 | 100% | — |

マッチングキー: `(rule_id, record_no, column)`。1件の重複報告・取りこぼしも誤差として数える。

## 3. 安全性基準

| ID | 基準 | 合格条件 |
|---|---|---|
| SEC-T1 | 元CSV不変 | G3 |
| SEC-T2 | CSVインジェクション | `=cmd|...`,`+`,`-`,`@`,TAB,CR始まりのセル値を含むCSVを検査し出力したCSV/xlsxの該当セルが、数式として解釈されない |
| SEC-T3 | HTML注入 | `<script>`,`"onerror=`等を含む値・列名・ファイル名を含むCSVのHTMLレポートで、スクリプトが実行されない（文字列としてエスケープ出力される）。外部リソース参照0 |
| SEC-T4 | ReDoS | `(a+)+$` 等の悪性パターン＋長い入力で、検査が**10秒以内**に終了（または明示的に拒否）|
| SEC-T5 | ルールJSON | 巨大(>10MB)・深い入れ子・未知キー・型違い・不正正規表現・列名重複のルールでクラッシュせず、位置付きエラーを表示 |
| SEC-T6 | 外部通信 | 検査〜出力の全工程で外部への接続試行0（CI上でネットワーク監視または送信遮断環境下で正常動作）。ソース内にHTTPクライアント使用がないことも確認 |
| SEC-T7 | ログ非漏洩 | 目印値（例 `CANARY_9f3a`）を含むCSVを検査し、ログ/診断ファイルに目印値が含まれない（履歴DBは除く＝D-03） |
| SEC-T8 | 出力先保護 | 入力と同一パスへの出力は拒否 |
| SEC-T9 | 履歴DB（D-03緩和策） | 「履歴全削除」実行後にDB内に実データ値が残らない／保存OFF設定時に値が保存されない／保存先パスが画面に表示される |
| SEC-T10 | 一時ファイル | 検査完了後、実データを含む一時ファイルが残らない |

| 項目 | 測定方法 |

## 7. 評価の運用ルール

1. 全案を**同一の** コーパス・runner・採点器・ルールセットで評価する。コーパス更新時は全案を再評価。
2. 評価は3回実行し、決定性を確認。速度は中央値。
3. 結果は `ARENA_RESULTS.md` に生データ(JSON)へのリンクと共に記録。
4. 各案は、評価用コーパスの**expected.jsonを閲覧できない**運用とする（ローカルGPTには渡さない・過学習防止）。GPTには**仕様記述と別途の公開サンプル（dev set）**のみ渡し、採点は非公開set（hold-out）で行う。
   - dev set: コーパスの約30%（公開）／hold-out: 約70%（非公開）。
5. 要件充足の自己申告は採用せず、トレーサビリティ表（要件ID→テストID→結果）で確認する。
