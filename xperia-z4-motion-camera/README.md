# Z4 MotionCam

Xperia Z4 を常時充電のまま使う、低発熱の見守りカメラアプリです。
動体を検知したときだけ録画し、同じ Wi-Fi にいるスマホや PC のブラウザから、ライブ映像と録画を見られます。

- 対象: Xperia Z4 (SO-03G / SOV31 / 402SO)。Android 5.0〜7.0 (minSdk 21 / targetSdk 25)
- 依存ライブラリなし（Android フレームワークの API だけを使用）。見る側はブラウザだけでよく、専用アプリは不要

## 要件と実装の対応

| 要件 | 実装 |
| --- | --- |
| 動体検知で録画 | プレビューを約 48 列のマスに分け、各マスの 4×4 の小さな模様（輝度のパターン）を背景の模様と比べ、**形が変わったマス**が一定以上あって 2回続けたら録画を開始します。明るさが変わっただけでは動きとみなしません（下の「明るさの変化は動きではない」）。動きが止まって N 秒たつと録画を止めます（`MotionDetector`, `CameraPipeline`） |
| LAN からライブ映像・録画を見る | 自前の小さな HTTP サーバーです。ライブは MJPEG、録画は Range 対応の MP4 配信で、シーク再生もできます（`HttpServer`, `assets/index.html`） |
| 外出先からの視聴 | ルーターのグローバル IP 宛てに HTTPS で公開します。ルーターのポート開放（UPnP）と、任意で DDNS 更新も自動で行います（`RemoteAccess`） |
| 録画データの管理 | 1 件ずつ保存・削除できるほか、チェックボックスで選んだ録画をまとめて保存（ZIP）・削除できます |
| 充電中でも熱暴走しない | 下の「発熱対策」を参照 |
| 30 秒でバックライト OFF | 最後のタッチから 30 秒で、輝度を最低にして黒一色の画面にします。画面の更新も止めます（`MainActivity`） |
| タッチでバックライト ON | 暗い間は、どこをタッチしても元の輝度に戻ります。復帰したときのタッチでボタンが押されることはありません |
| 稼働記録 | 起動時刻と稼働時間を記録します。1 分ごとに「動作中」の記録を書くので、突然電源が切れても、最後の記録時刻（誤差 1 分以内）と直前の電池の状態が残ります（`UptimeLog`） |
| 容量がいっぱいなら古い録画を削除 | 録画を始めるときと、録画中は 15 秒ごとに空き容量を確認します。設定値を下回ったら古いファイルから削除します（`RecordingStore`） |

## 発熱対策

既存の見守りカメラが熱暴走した原因は、常時フル稼働で処理していることだと考えています。
Z4 の SoC である Snapdragon 810 は発熱しやすいことで知られています。
そこで、必要なときだけ必要なぶんだけ処理するように作りました。

1. **カメラは低解像度・低フレームレート**: 標準は 640×480・10fps です。設定値に届く中で最も遅いフレームレート範囲を選び、下限も低いものを選ぶので、暗い部屋でも無理に高感度にしません。
2. **待機中はカメラ自体を遅く動かす**: 録画しておらず誰も見ていない間は、センサーを 5fps 前後で動かします（動体検知には十分）。動きを検知したりライブを開いたりすると、設定のフレームレートに上がります。電池温度が 42℃ を超えたら、録画中も遅いままにします。
3. **エンコードは録画中だけ**: 監視中は動体検知しか動かしません。録画中だけハードウェアの H.264 エンコーダ（MediaCodec）を使い、ソフトウェアエンコードはしません。録画の日時表示は、エンコーダに渡す前の色形式の変換（もともと毎コマ行っている）のあとに、左下の小さな枠（640×480 で約 5,000 画素、1 コマの約 1.7%）を書き換えるだけです。文字は秒が変わったときにだけ作り直し、GPU も使いません。
4. **動体検知はとても軽い**: どの解像度でも 1 フレームあたり約 4 万画素を読むだけです（約 48×27 マス × 16 点 × 2 画素。解像度が高いほど間引きます）。これを 1 秒に 3 回まで行います。
5. **JPEG は見ている人がいるときだけ作る**: ライブ映像を見ている人がいなければ、JPEG 圧縮は一切しません。1280 幅以上ではライブ映像を縦横半分にしてから圧縮します（録画は元の解像度のまま）。ブラウザのタブを隠すとライブは自動で止まります。見っぱなしでも 10 分で止まり、「ライブ再開」ボタンで続きを見られます。
6. **画面の描画を止める**: 暗い間はプレビューも文字も更新しません。明るい 30 秒間だけ 0.5 秒ごとに更新します。
7. **外部との通信は最小限**: IP 確認サービスなどには一切接続しません。外出先視聴を有効にしたときだけ、30 分に 1 回ルーターのポート開放を更新します（DuckDNS を設定した場合はその更新も）。正規の証明書（Let's Encrypt）の取得は、約 2 か月に 1 回、1〜2 分で終わります。
8. **電池温度で段階的に負荷を下げる**（`ThermalPolicy`。戻るときは 2℃ のヒステリシスあり）:

   | 電池温度 | 動体検知 | ライブ | 録画 fps |
   | --- | --- | --- | --- |
   | 39℃ 未満 | 3 回/秒 | 5 fps | 設定値 |
   | 39℃ 以上 | 2 回/秒 | 2 fps | 最大 8 |
   | 42℃ 以上 | 1 回/秒 | 1 fps | 最大 5 |
   | 45℃ 以上 | **カメラを一旦解放して冷却を待ちます**（43℃ を下回ると自動で再開。録画中のファイルは正しく閉じます） |

   45℃ で止める理由: 端末が熱で強制終了すると、その後は何も記録できません。短時間止めて冷ますほうが、失う時間が少なく済みます。

9. **再起動からの復帰**: 端末が起動すると自動で監視を再開します（設定でオフにできます）。

### 端末側でやっておくと効果が大きいこと

- **急速充電器（Quick Charge）を使わない**: 5V/1A 程度の普通の充電器にします。充電による発熱が大きく減ると考えられます。
- **いたわり充電（Battery Care）をオンにする**: Android 6 以降の Xperia にある機能です。満充電のまま充電し続ける時間を減らせます。
- ケースを外し、放熱しやすい向き（背面を浮かせる）で設置します。直射日光と布団の上は避けてください。
- 画面ロックを「なし」にします。停電などで再起動したとき、ロック解除なしで監視を再開するためです。
- 自動アップデートと不要なアプリを止め、裏で動く処理を減らします。

2. ダウンロードした APK を開いてインストールします。

注意: このAPKは開発環境で作った署名鍵で署名しています。**別の鍵で署名されたAPKでは上書き更新できません。** その場合は一度アンインストールが必要で、アンインストールすると保存済みの録画（`Android/data/com.z4motioncam/`）も消えます。更新するときは先に録画を退避してください。

## ビルドとインストール

Android Studio（JDK 17 以上）でこのフォルダ `xperia-z4-motion-camera/` を開き、そのままビルドします。

```sh
cd xperia-z4-motion-camera
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`./gradlew test` で PC 上の単体テストを実行できます。対象は動体検知、監視の状態機械（低電池・おやすみ時間・時計とタイムゾーンの変更・再起動後の復元）、人認識の判定、更新の取得・検証（ローカルの HTTP / HTTPS サーバーを相手に、再開・改ざん・署名違い・容量不足など）、温度制御、ストレージ削除、HTTP（Range・削除・ZIP・認証）、HTTPS、UPnP、色変換・縮小、証明書の取得（ACME）です。

証明書の取得は、Let's Encrypt のテスト用認証局 [Pebble](https://github.com/letsencrypt/pebble) を相手に実際の発行まで試せます（環境変数 `PEBBLE_CA` がないときは省略されます）。

```sh
pebble-challtestsrv -management 127.0.0.1:8055 -dns01 127.0.0.1:8053 -http01 "" -https01 "" -tlsalpn01 "" &
PEBBLE_VA_NOSLEEP=1 pebble -config pebble-config.json -dnsserver 127.0.0.1:8053 &   # listenAddress 127.0.0.1:14000
PEBBLE_CA=pebbleのHTTPS証明書の発行元.pem ./gradlew test
```

Z4 に入れるには、「設定 > セキュリティ > 提供元不明のアプリ」を許可してから APK を入れてください。

Android Studio を使わずに作る場合は、Ubuntu のパッケージ（`aapt` `apksigner` `zipalign` `dalvik-exchange` `android-sdk-platform-23`）を入れて `./build-apk.sh` を実行します。`release/` に署名済み APK ができます。

## 使い方

1. アプリを起動し、カメラの権限を許可します。
2. 画面左上に `http://192.168.x.x:8080/` が出るので、同じ Wi-Fi のスマホや PC のブラウザで開きます。
   - 上に状態（録画中か、電池残量・温度・充電状態、空き容量、最後に動きを検知した時刻）、その下にライブ映像と録画一覧が出ます。
   - 録画一覧は「チェックボックス｜サムネイル｜録画時間｜録画日時｜保存｜削除」の並びです。サムネイル（約 5KB の小さな JPEG）は、録画が終わった直後にバックグラウンドで 1 回だけ作ります（動画の 1 秒付近の 1 コマ。端末の標準のデコーダ使用）。この版より前の録画は、一覧を開いたときに 1 件ずつ順に作ります。録画を削除・自動削除すると、サムネイルも一緒に消えます。日時をタップすると再生します。録画一覧は枠の中でスクロールします。動画をタップすると、再生画面の下の一覧がスクロールして、再生中の動画の行（緑の印・「▶ 再生中」）が一覧の先頭、つまり再生画面のすぐ下に来ます。次に見る動画は、その下の行です。
   - 各録画の右にある「保存」でダウンロード、「削除」で削除します（確認あり）。
   - 左のチェックボックスで録画を選び、一覧の上にある「一括保存」「一括削除」を押すと、選んだ録画だけをまとめて処理します。「すべて選択」で全件を選べます。
   - 一括保存は、1 件なら MP4 のまま、2 件以上なら 1 つの ZIP（無圧縮で、スマホ側の負荷はほとんどありません）で保存します。ZIP は合計 3.9GB までです（Android 7 未満は 4GB を超える ZIP を作れないため）。
   - 録画中のファイルは一覧に出ないので、削除されることはありません。
   - 状態、電池温度、空き容量、最後に動きを検知した時刻も表示されます。
   - 一番下の「設定」で、Z4 の設定画面と同じ項目をブラウザから変更できます（保存すると数秒で Z4 に反映）。パスワードなどの秘密の値は表示されず、変更するときだけ入力します。
3. 30 秒たつと画面が暗くなります。タッチすると 30 秒間だけ元に戻ります。
4. **監視のオン・オフ**: ブラウザ上部の「監視オフ／監視オン」ボタン、または Z4 画面の同じボタンで切り替えます。
   - オフの間はカメラを止めます（動体検知・録画・ライブ映像なし。発熱が最も少ない状態）。録画中だったファイルは正しく保存してから止めます。
   - オフの間も閲覧用のサーバーは動き続け、Z4 の画面は暗いまま眠らないので、家の中・外出先のどちらからでもいつでもオンに戻せます。
   - オン・オフの状態は再起動しても保たれます。
5. Z4 画面の「終了」はアプリ自体を終了します（確認あり）。終了するとブラウザからは再開できないので、カメラだけ止めたいときは「監視オフ」を使ってください。

| フレームレート（録画） | 10 fps | 1 / 2 / 3 / 5 / 7 / 10 / 15 / 20 / 24 / 30。低いほど発熱が減ります。20 以上は非推奨です |
| 映像の回転 | 0° | 設置の向きに合わせます（録画とライブの両方に反映） |
| 検知感度 | 中 | 「高」は寝返りのような小さな動き向け。誤検知が多ければ「低」にします |
| 録画を続ける秒数 | 10 秒 | 動きが止まってから録画を止めるまでの時間（5 / 10 / 20 / 30 / 60 / 90 / 120 / 180 秒） |

| 動画に日時を入れる | オン | 録画の左下に撮影日時（端末の時計、`2026/09/28 03:12:45` の形）を白文字・黒地で入れます。ダウンロードした動画でもいつの映像か分かります。負荷は下の「発熱対策」を参照 |
| SD カードを優先 | オン | microSD があればそこに保存します |
| 確保する空き容量 | 500 MB | これを下回ると、古い録画から削除します |
| ポート番号 | 8080 | 家の中（LAN）用。パスワードは不要です |
| 外出先からの視聴を有効にする | オフ | 下の「外出先からの視聴」を参照 |
| 外出先視聴用パスワード | （なし） | 8 文字以上。外出先（HTTPS）からだけ求められます（ユーザー名は何でも可） |
| 外部アドレス（グローバル IP） | （なし） | 外出先 URL に使います。空欄ならルーターが報告する IP を使います |
| 外出先用ポート番号 | 8443 | HTTPS 用。LAN 用ポートと別の番号にします |
| ルーターのポートを自動で開放（UPnP） | オン | オフのときはルーターで手動の転送設定が必要です |
| DuckDNS ドメイン名 / トークン | （なし） | 任意。IP が変わっても同じ URL で接続できます |
| 正規の証明書を自動取得（Let's Encrypt） | オフ | DuckDNS が必要。Google スプレッドシートのビューアで見るときは必須です（下の「正規の証明書」） |
| 検知モード | 動体検知 | 「動体検知」は動きがあれば録画（従来どおり）。「人を認識」は人が写っていると判断したときだけ録画します（下の「検知モードと人認識」） |
| 人認識の厳しさ | 標準 | 厳しい / 標準 / ゆるい。顔が見えれば人とみなすほか、動く範囲の形（シルエット）でも判定します。厳しい＝大きく人らしい形だけ、標準＝中間、ゆるい＝暗い小さな影も拾う（カーテン・ペットで誤検知しやすい） |
| 電池がこの%を切ったら一時停止 | 18 | 0 で無効。下の「電池が少ないとき・おやすみ時間」 |
| この%まで充電したら再開 | 50 | 停止レベルより 5% 以上高くします |
| おやすみ時間は充電に専念 | オン | |
| おやすみ時間の開始 / 終了 | 03:00 / 04:00 | 「時:分」。23:00〜01:00 のように日をまたげます。開始と終了が同じなら無効 |
| おやすみ時間でも監視を続ける電池% | 80 | この%以上なら監視を続けます（5% 下がるまで止めません） |
| 1日1回、新しい版を自動で確認 | オン | 下の「アプリの更新」 |
| 更新情報の URL | このリポジトリの release/update.json | https のみ |
| 期待する APK の SHA-256 | （なし） | 任意。別の経路で確かめた値 |
| 起動時に自動で開始 | オン | |
| 画面を点けたまま前面に保つ | オン | ほかのアプリやホーム画面が前面に出たら 1 分後、画面が消えたら 5 秒後に、このアプリを前面に戻して画面を暗く点けたままにします（下の「背面・スリープで止まらないように」） |

これらの設定は、閲覧側のブラウザ（「設定」欄）からも変更できます。家の Wi-Fi につながっている人は誰でも変更できる点に注意してください（外出先からはパスワードが必要です）。

録画は `Android/data/com.z4motioncam/files/Movies/recordings/`（SD カードまたは内部ストレージ）に `yyyyMMdd_HHmmss.mp4` という名前で保存されます。

## 背面・スリープで止まらないように

監視はフォアグラウンドサービス（通知に常駐）で動くので、本来は画面が消えても続きます。ただ、端末によっては、アプリが背面に回ったり画面が消えたりすると、カメラやアプリそのものを止めてしまいます（省電力機能・利用時間の制限など）。そこで次の 3 つで守ります。

1. **前面に戻す**（設定「画面を点けたまま前面に保つ」、標準オン）: 画面が消えたら 5 秒後に画面を点けてアプリを前面に戻し、すぐ暗くします。ほかのアプリが前面に出た場合は、少し使えるように 1 分待ってから戻します。10 分間に 6 回戻しても閉じられる場合は、端末側の制限と判断して 30 分休みます（何度も点けたり消したりしないため）。
2. **カメラの見張り**: 映像が 15 秒届かなければ（エラーの通知がないまま止まる機種があるため）、カメラを開き直します。録画中だったファイルは保存されます。
3. **起動時**: 端末の起動後、画面より先に監視（サービス）を始めます。

**Android 10 以降**は、背面のアプリが自分の画面を開くことが制限されています。最初に表示される案内から「他のアプリの上に重ねて表示」を許可してください（設定 > アプリ > Z4 MotionCam からも変更できます）。

何が起きたかは、ブラウザの「稼働記録」の「出来事」で確認できます。

## 検知モードと人認識

設定「検知モード」で切り替えます（Z4 の設定画面でも、ブラウザの「設定」でも変更できます）。現在のモードは Z4 の状態画面とブラウザ上部の状態に出ます（`/api/status` の `mode`、`person`）。

| モード | 録画を始める条件 | 録画を止める条件 |
| --- | --- | --- |
| **動体検知**（標準） | 動きを 2 回続けて検知 | 動きが止まって「録画を続ける秒数」が過ぎたとき |
| **人を認識** | 動きがあった直後の 4 秒間だけ人判定を行い、直近 3 回のうち 2 回（最後の回を含む）が「人あり」 | 最後に「人あり」と判定してから「録画を続ける秒数」が過ぎたとき |

人認識でも発熱を抑えるため、**動体検知を門番**にしています。動きがなければ人判定は一切動きません。録画中だけは、止まって座っている人を逃さないよう 2 秒に 1 回判定します（電池温度が上がると間隔を 2〜4 倍に広げます）。**間引き（バックオフ）**: 録画していないとき、「人なし」の判定が 3 回続くと、その後は 1 回ごとに次の判定までの間隔を 2 倍ずつ広げます（0.5 秒 → 1 → 2 → 4 → 8 → 最大 12 秒）。カーテンのように「動くが人ではない」ものが揺れ続けても、判定は 10 分で 60 回以下に収まります（合成テストで確認）。「人あり」が出たとき、録画を始めたとき、動きが 10 秒止まってからまた動いたときは、すぐ元の 0.5 秒間隔に戻ります（人が入ってきても、遅くとも 12 秒以内に見つけ、見つけた直後は素早く 2 回目の確認をします）。録画中の 2 秒ごとの判定には適用しません。人判定は 1 回あたり 320 ピクセルの小さな灰色画像 1 枚だけを扱います。顔検出は 1 回ごとに外れることがあるので、人認識では「録画を続ける秒数」を 20〜30 秒にすることをお勧めします。

### 明るさの変化は動きではない（動体検知・人認識の両方）

`MotionDetector` は明るさの差ではなく**模様の相関**で動きを判定します。各マスの 16 点から平面（明るさの傾き）と平均を引いた「形」を、背景の形と正規化して比べます（相関の 2 乗が 0.70 未満なら、形が変わったマス）。全体の明るさの増減・ガンマ・ランプ・日だまりのぼやけた縁は形を変えないので動きになりません。暗所のセンサーノイズは、画面全体のノイズ量を毎フレーム推定して基準に加えるので動きになりません。白とび・黒つぶれのマスは無視します。画面の 60% 以上で平均輝度が同じ向きに大きく動いたとき、または変化したマスが大半で明るさの向きがそろっているとき（照明の点灯・消灯、自動露出の変化、待機 5fps⇄録画の切替直後）は「照明の変化」として背景を取り直し、2 回分見送ります。模様のない（平らな）マス同士は、明るさが違っても動きとみなしません。人が動くと、そのマスの縁や模様が変わるので検知できます。

### 形（シルエット）による人判定（`SilhouetteTracker`、外部ライブラリなし）

動体検知の「変化したマス」を、直近 2 秒分重ねた輪郭（動いた腕だけでも数秒で全身の輪郭になる）にして、つながった塊ごとに次を見ます。画像の回転設定は、向きを直したあとの座標で判定します。

| 見るもの | 内容 |
| --- | --- |
| 大きさ | 高さ・外接長方形の面積・幅（画面に対する割合）。遠い小さな人から、画面の半分を占める塊（人ではない）まで |
| 形 | 縦横比（立つ 0.2〜0.9、座る 約1、横たわる 1.5〜5）、外接長方形の充填率（ノイズや細い筋は低い） |
| 縦の芯 | 全体は横に広くても、背の高い狭い芯があれば立った人（床の影・引きずる布） |
| カーテン | 画面の上端から下がる背の高い塊は除外。大きな塊が同じ場所で左右に揺れ続けるのも除外（重心の反転が 3 回以上で行って戻る） |
| 持続 | 直近 4 秒に何回その塊が見えたか（厳しい 4 / 標準 3 / ゆるい 2 回以上）。1 回きりの閃光は人ではない |
| 暗い場面 | 平均輝度 40 未満のとき、標準・ゆるいは大きさの下限を緩める（面積 1/2、高さ 3/4）。平均輝度 14 未満では顔検出を呼ばない |

3 段階の対応（高さ / 面積 / 縦横比の上限 / 充填率 / 持続）: 厳しい 30% / 6% / 1.3 / 45% / 4 回、標準 22% / 3.5% / 3.5 / 35% / 3 回、ゆるい 12% / 1.2% / 5 / 25% / 2 回。顔が見つかればどの段階でも人とみなします。人認識の動体の門番は、形で絞るので最も敏感な面積しきい値（0.6%）にします。値は `SilhouetteTracker.params` にあります。**これらは PC 上の合成画像と、実写真 2 枚から見積もった人の大きさ（逆光の人 画面幅 28%×高さ 66%、暗い戸口の影 9%×39%）でしか確かめていません。**

### 方式の選定（`PersonDetector` インターフェース）

検出器は `PersonDetector` として切り出してあり、`HybridPersonDetector` を使っています。検討した方式は次のとおりです。

| 方式 | 精度 | 負荷 | このアプリでの可否 |
| --- | --- | --- | --- |
| **android.media.FaceDetector**（採用・主） | 正面〜やや斜めの顔だけ。横向き・うつ伏せ・暗所は見逃す。ペットやカーテンを人と誤認しにくい | 320×240 で 1 回 数十 ms 程度（実機未測定） | API 1 から標準。**追加ファイルなし**、`build-apk.sh` のまま、Android 5.0 で動く |
| **動く領域のシルエット解析**（採用・全段階） | 後ろ向き・暗い影・横たわる人も、大きさ・形・持続で判定。大きなペットや荷物は誤検知しうる | 約 48×27 マスの連結成分だけ（1 回約 20 マイクロ秒、PC 実測） | 追加ファイルなし。厳しさで条件が変わる |
| TFLite + 軽量な人検出モデル（見送り） | 3 つの中で最も高い（横向き・全身・暗めの画像にも強い） | Snapdragon 810 の CPU で 1 回 50〜100 ms 級。動体検知を門番にしても発熱要因になる | 下の理由で今回は組み込まず |
| ソフトウェアの HOG 等を自作 | 精度が低く、実装と検証の負担が大きい | CPU 重い | 見送り |

**TFLite を組み込まなかった理由（正直な記録）**:

1. 大きさ: 現在の APK は約 110 KB です。`org.tensorflow:tensorflow-lite:2.16.1` の AAR は Maven Central で 6.2 MB（4 つの ABI を含む。Z4 に必要な `arm64-v8a` / `armeabi-v7a` だけでも合計 2〜3 MB の `.so`）で、これに量子化済みの人検出モデル（数 MB）が加わり、APK は **約 50〜80 倍（5〜8 MB）** になります。
2. ビルド: `build-apk.sh`（aapt + dalvik-exchange）に、AAR の展開・`classes.jar` の dex 化・`lib/<abi>/*.so` の APK への格納（`aapt add` は ZIP のパスを保つ）・`zipalign` での `.so` の 4 KB 整列を追加する必要があります。この作業環境には ARM の実行環境と `dalvik-exchange` / `apksigner` が無く、**ビルドも実行も確認できません**。確認できないネイティブコードを、突然の電源断が許されない見守り用途に入れるのは責任を持てないと判断しました。
3. Android 5.0 での動作: 新しい TFLite は NDK の C++ 実行環境（`libc++_shared`）に依存し、Android 5.0 での動作は実機でしか確かめられません。
4. モデルの入手元・ライセンス: Apache-2.0 のモデル（TensorFlow Hub / TF Model Zoo の SSD MobileNet 系）を使えますが、配布 URL の固定と SHA-256 の確認をビルド手順に入れる必要があります。

差し替え方: `PersonDetector` を実装したクラスを作り、`CameraPipeline.open()` の `new HybridPersonDetector(...)` を置き換えるだけです。判定の流れ（`PersonGate`）はそのまま使えます。

### 誤検知・見逃しの傾向としきい値の調整

| 状況 | 起きやすいこと | 対処 |
| --- | --- | --- |
| 顔が正面〜斜めでよく見える | 検知できる | |
| 寝ていて横向き・うつ伏せ、顔が布団で隠れる | 形で拾えることがある（横たわる形は標準・ゆるいで有効） | 見逃すときは「ゆるい」か動体検知に戻す。見逃しが許されない用途では動体検知を使ってください |
| 真っ暗・逆光 | 見逃す | 常夜灯を点ける |
| ぬいぐるみ・ポスターの顔 | まれに誤検知（動きがなければ判定自体が動かない） | 「厳しい」にする |
| 「ゆるい」でペット・荷物・人の影 | 誤検知しやすい | 「標準」に戻す |

しきい値は `HybridPersonDetector.faceThreshold`（顔の確からしさ: 厳しい 0.55 / 標準 0.42 / ゆるい 0.30。FaceDetector の値は明瞭な顔で 0.4〜0.6 程度）と、`BlobAnalyzer` の定数（人とみなす塊の大きさ 4〜65%、詰まり具合 40% 以上、縦横比 0.25〜4）です。録画の開始が早すぎる・遅すぎるときは `PersonGate` の `NEED` / `HISTORY` / `MOTION_WINDOW_MS` を調整します。**これらの値は PC 上の合成画像でしか確かめていません**。実機で様子を見て調整してください。

## 電池が少ないとき・おやすみ時間（監視の状態機械）

カメラを動かしてよいかは `MonitorPolicy`（純 Java）の 1 か所だけで決めます。停止の理由は互いに上書きせず、**別々の理由**として持ちます。1 つでも理由があればカメラは止まり、すべて解消すると再開します。

| 優先順位 | 理由 | 解消条件 |
| --- | --- | --- |
| 1 | 手動オフ（ブラウザ・Z4 の「監視オフ」） | 手動でオンにする。電池や時刻では**書き換えません** |
| 2 | 更新の導入中（導入画面を出してから最大 3 分） | 画面が閉じられる、または時間切れ |
| 3 | 高温（`ThermalPolicy` が CRITICAL。従来どおり 45℃ で止め、43℃ で解除） | 温度が下がる |
| 4 | 低電池 | 電池が 18% 未満になると停止し、**50% 以上**になるまで再開しません |
| 5 | おやすみ時間（充電専念） | 時間帯が終わる、または下記 |

- **おやすみ時間**: 毎日 03:00〜04:00（設定で変更）は監視を止めて充電に専念します。ただし電池が 80% 以上なら監視を続けます。時間帯に入ったときに 80% 以上なら続け、そこから **75% を下回るまでは止めません**。止まっている間は **80% 以上になるまで再開しません**。80% 付近でオンオフを繰り返しません。開始 > 終了（23:00〜01:00）なら日をまたぎます。
- 状態画面・ブラウザには、止まっている理由を日本語で出します（`/api/status` の `policy.text`、`policy.reasons`）。複数あるときは優先順位の高い順にすべて並べます。
- **再起動しても復元**します。低電池の一時停止とおやすみ時間の状態は保存されるので、再起動したときに電池が 18〜50% なら、一時停止のままです。
- **異常系**: 電池の値を読めないとき（0〜100 以外）は、新しい停止をしません（すでに止まっているなら、その状態を保ちます）。電池の値による切り替えは、**20 秒続いてから**実行します（センサーの 1 回だけの異常値では切り替わりません）。端末の時計が 2020 年より前（未設定）の間は、おやすみ時間を適用しません。時計の変更・タイムゾーンの変更・日付またぎは、15 秒ごとと変更通知のときに時計を読み直すだけで正しく扱えます（時計が大きく変わったときは出来事に記録します）。
- **すべての遷移は、稼働記録の「出来事」に記録**します（例: 「電池が17%に下がったため、監視を一時停止しました（50%まで充電して再開します）」）。

## アプリの更新（USB なしで新しい版を入れる）

ケーブルも PC のつなぎ直しも要りません。入口は **2 つ**あり、Z4 の「更新」ボタンと、ブラウザの「アプリの更新」欄のどちらにもまとめて出ます。**どちらの入口で受け取った APK も、同じ検証（下の表）と同じ導入の流れ**を通り、同じフォルダに保存されます（`UpdateEngine` / `UpdateStore`）。最後は必ず Z4 の前の人が Android の確認画面で「インストール」を押します（サイレント導入はしません）。

| 入口 | 向いている場面 | しくみ |
| --- | --- | --- |
| **インターネットから確認**（プル型） | 公開できる APK を `release/` などに置いているとき | Z4 が自分で更新先（https）を見に行く。1 日 1 回自動 |
| **ブラウザから送る**（プッシュ型） | **自宅の IP を埋め込んだ個人用 APK**（公開リポジトリに置けない）、手元の PC からそのまま渡したいとき | 同じ Wi-Fi のブラウザから APK を送る。Z4 の画面にだけ出るワンタイムコードが必要 |

### 入口 1: インターネットから確認（プル型）

1. 新しい版があると、Z4 の画面に「更新: 新しい版 x.y があります」と出て、ブラウザの「アプリの更新」にも表示されます（1 日 1 回、自動で確認します）。いつでも Z4 の「更新」ボタン →「インターネットから確認」、またはブラウザの「インターネットから確認」で確認できます。
2. 「インターネットから取得」（ブラウザでは「ダウンロード」）を押すと、APK を取得して**検証**します。通信が途中で切れても、次に押すと続きから再開します。
3. 「更新を導入」（ブラウザでは「導入画面をZ4に表示」）を押すと、Z4 に Android 標準のインストーラ画面が出ます。**Z4 の画面で「インストール」を押して**ください。導入中は監視を止め、録画中のファイルは正しく閉じます。導入が終わるとアプリが自動で再開します（`MY_PACKAGE_REPLACED`）。
4. 「提供元不明のアプリ」が許可されていないときは、必要な操作（Android 7.1 以前: 設定 > セキュリティ > 提供元不明のアプリ、Android 8 以降: このアプリの「不明なアプリのインストール」）を画面に出し、その設定画面を開きます。

### 入口 2: ブラウザから送る（プッシュ型・LAN 限定）

1. Z4 の画面で「更新」→「**ブラウザから送る**」を押します。6 桁のコードが **Z4 の画面だけ**に表示されます（10 分間・1 回だけ有効）。
2. 家の Wi-Fi のブラウザで、「アプリの更新」の「ブラウザから送る」を開き、新しい APK（上限 30 MB）を選び、コードを入力して「更新を送る」を押します。PC の `sha256sum` と見比べられるよう、受け取ったファイルの SHA-256 を表示します。
3. 検証に通ると、入口 1 の手順 3 と同じく、Z4 の「更新」ボタンから導入します（ブラウザの「導入画面をZ4に表示」でも可）。

安全策（LAN の HTTP はパスワードなしの設計なので、受け付けを無条件にはしていません）:

- **端末の画面でだけ見えるワンタイムコード**: 受け付けは Z4 の画面で人が押したときだけ始まり、コードは `/api/status` や `/api/update` には出ません。同じ Wi-Fi にいるだけの人や、悪意のあるページは送れません。コードを 5 回間違えると終了し、受け付けに成功しても終了します（1 回限り）。
- **LAN 限定**: 外出先（HTTPS）からは、パスワードがあっても受け付けません。外出先からはコードが見えず、導入には Z4 の前の人が必要なため、「開ける」より「閉じておく」ほうが安全と判断しました。
- **CSRF 対策**: `POST /api/update/push` には `X-Z4-Action: update` ヘッダ（と `X-Z4-Code`）が必要です（`/api/delete` などと同じ方式）。ほかのサイトからは、ブラウザの制限でこのヘッダを付けて送れません。
- **ストリーム受信**: 本体は 256 KB の通常の POST の上限とは別に、メモリにためず 1 本のファイルへ書き込みます。`Content-Length` が 30 MB を超えれば読む前に拒否し、途中で切れたものはその場で消します。同時に受けるのも、ほかの更新作業（確認・取得中）と重ならない 1 件だけです。

### 共通の検証（上から順に確認し、1 つでも外れたら導入画面を出しません）

| 確認 | プル型 | プッシュ型 |
| --- | --- | --- |
| https のみ | 更新情報・APK のどちらも `https://` だけ（転送の途中で http に落とすものも拒否）。証明書とホスト名は OS が検証。Android 7 以前に無いルート証明書は同梱の `cacerts.pem` で補う | （LAN の HTTP。コードで受け付けを制限） |
| 別経路の SHA-256（任意） | 設定「期待する APK の SHA-256」に、別の経路で確かめた値を入れておくと、更新情報の値と一致しない限り何も取得しない | — |
| 大きさ・形式 | 更新情報の `size` と一致（20 KB〜64 MB）、ZIP として開け、`AndroidManifest.xml` と `classes.dex` を含む | 20 KB〜30 MB、同じ ZIP の検査 |
| SHA-256 | ダウンロードしたファイルが更新情報の `sha256` と一致。違えば破棄 | 受け取ったファイルの SHA-256 を保存し、表示する（導入直前の再確認に使う） |
| **署名の読み取り（改ざん検出）** | APK の全ファイルを JAR 署名の検証で最後まで読み、書き換え・後から足されたファイルがないか確かめる（共通） | 同左 |
| 中身の確認 | パッケージ名が `com.z4motioncam`、`versionCode` が更新情報どおりで、今の版より新しい | パッケージ名が同じで、今の版より新しい（同じ版・古い版への戻しは拒否） |
| **署名者の一致** | APK の署名証明書が、今入っているアプリと**完全に同じ**であること。違えば拒否し、理由を日本語で表示（「別の鍵で署名された版です。入れ替えには一度アンインストールが必要で、録画も消えます」）。最も重要な防御で、更新情報・取得元・送った人が偽物でも、署名鍵を持たない人は通過できない | 同左 |
| 導入直前の再確認 | 導入画面を出す直前に、保存したファイルの SHA-256・構造・署名をもう一度確認する | 同左 |
| Android の確認 | 最後に Android 標準の画面で人が承認。上書き更新なので、録画（`Android/data/com.z4motioncam/`）と設定は残る | 同左 |

失敗への対処: 通信失敗は 30 分・1 時間・2 時間…（最大 6 時間）と間隔を空けて自動でやり直します。空き容量が足りないときは、必要な量（APK + 約 20 MB）を表示して中止します。書きかけのファイルは、別のファイルに替わったとき・3 日以上たったとき・導入済みの版になったとき・形式や署名が不正だったとき・送信が途中で切れたときに自動で消します（起動時と次の受信の前にも掃除します）。プルの確認は 1 日 1 回だけ（更新情報は 16 KB 以下）で、新しい版があってもダウンロードは操作したときだけです。端末が熱いとき（42℃以上）は自動の確認を見送ります。ブラウザから受け取った APK は、より新しい版が更新先に見つかるまで（同じ版以下なら）そのまま導入待ちとして残ります。

更新を公開する側の手順（プル型）:

```sh
VERSION_CODE=12 VERSION_NAME=1.12 ./build-apk.sh                       # 以前と同じ署名鍵で署名する
./make-update-manifest.sh release/z4motioncam-1.12.apk 12 1.12 "変更点"   # release/update.json を作る（SHA-256 を表示）
```

`release/update.json` と APK を同じフォルダに https で置きます（標準の更新先はこのリポジトリの `release/` フォルダです）。更新先を変えたいときは、設定の「更新情報の URL」、またはビルド時の `UPDATE_URL=https://…/update.json ./build-apk.sh` で指定します。`versionCode` は必ず増やしてください。**自宅の IP を埋め込んだ個人用 APK（下の「個人用ビルド」）は公開リポジトリに置かず、入口 2 で送ってください。**

限界: 署名鍵が違う版は、どれだけ検証しても上書きできません（Android の仕様）。署名が v1（JAR 署名）のない v2 のみの APK は、JAR の改ざん検出が効かないため、パッケージマネージャの読み取りと Android の確認に任せます（`build-apk.sh` は最小 SDK 21 で署名するので v1 も付きます）。Android 8 以降でバックグラウンドから導入画面を出せるかは、機種や設定によります（実機では Android 5.0 が対象）。Android 5.0 のインストーラは content:// を受け付けないため、Android 6 以前は `file://`（アプリ専用の外部フォルダ）で渡し、7 以降は読み取り専用の ContentProvider（`UpdateFileProvider`）で渡します。実機の Android 5.0 の標準インストーラの動き（提供元不明のアプリの案内画面を含む）は、実機では未確認です。

## 稼働記録（突然の電源断の調査）

ブラウザの「稼働記録」欄で、次のことが分かります。

- **現在の稼働時間**と開始時刻
- **過去の稼働**: 開始 → 終了（最後に動作を確認した時刻）、稼働時間、終わり方、直前の電池の状態
- **電池の記録**: 5 分ごとの電池残量・温度・電圧・充電状態・負荷制御レベル（直近 24 時間を表示。7 日分を保存）
- **出来事**: 画面が消えた、アプリが背面に回った、前面に戻した、カメラの映像が止まって開き直した、ほかのアプリにカメラを取られた、など（新しい順）

アプリは 1 分ごとに「動作中」をストレージへ書き込みます（記録内容は電池と負荷の状態だけで、発熱への影響はありません）。
次に起動したとき、前回の記録が閉じられていなければ「突然止まった」と判断し、最後の書き込み時刻を終了時刻として残します。

| 終わり方 | 判定の仕方 |
| --- | --- |
| 停止ボタン（アプリ停止） | 停止したときに記録 |
| 端末のシャットダウン・再起動 | OS のシャットダウン通知を受けて記録（電源メニュー、OS による電池切れ・過熱の停止を含む） |
| **突然の電源断**（通知なし） | 次の起動時、端末の起動からの経過時間がリセットされていることで判定 |
| アプリだけが強制終了 | 次の起動時、起動からの経過時間が続いていることで判定 |

「直前の状態」の見方の例:

- 充電が「接続中・充電停止」で、温度が高く、電池残量が少ない → 熱で充電が止まり、電池切れで落ちた
- 温度が高く、電池残量が多い → 本体の過熱で落ちた
- 温度も残量も問題ない → 電池の劣化や本体の異常

## 外出先からの視聴

ルーターにグローバル IPv4 が割り当てられている環境で使えます（ルーターの WAN 側 IP と、https://api.ipify.org に表示される IP が同じなら該当します）。

### 有効にする

1. Z4 の「設定 > 外出先からの視聴」で、**外出先視聴用パスワードを 8 文字以上**にします。
2. 「外出先からの視聴を有効にする」をオンにします。
3. 「外部アドレス」にグローバル IP を入れます。空欄のままでも、ルーターが UPnP で報告する IP を使います。
4. 任意で DuckDNS を設定します。https://www.duckdns.org で無料のサブドメインを作り、ドメイン名とトークンを入力します。グローバル IP が変わっても、同じ URL で接続できるようになります。
5. 任意で「正規の証明書を自動取得（Let's Encrypt）」をオンにします（下の「正規の証明書」）。
6. Z4 の画面と、LAN のブラウザの「外出先からの視聴」欄に、外出先用の URL と証明書の状態が出ます。

UPnP が使えないルーターでは、ルーターの管理画面で TCP 8443 番を Z4 の LAN IP の 8443 番へ転送してください（下の「ポートマッピング」）。

### ポートマッピング（手動のポート転送）

1. Z4 の LAN IP を固定します（ルーターの「DHCP 固定割当」などで、Z4 の MAC アドレスに IP を割り当てる）。
2. ルーターのポートマッピング（ポート転送）に、TCP・外出先用ポート → Z4 の LAN IP・同じポートを追加します。
3. Z4 の設定で「ルーターのポートを自動で開放（UPnP）」をオフにします。

**v6プラス / OCN バーチャルコネクトなど（IPv4 over IPv6・MAP-E 方式）の場合**: グローバル IPv4 を複数の契約者で共有するため、使えるポート番号が決まっています（例: Aterm では「利用可能ポート」に 5872-5887 などの範囲が表示されます）。8443 は使えないことが多いので、**利用可能ポートの範囲から 1 つ選び、ルーターと Z4 の「外出先用ポート番号」を同じ番号にしてください。** 1023 以下のポートは使えません。

ルーターが報告する IP が「外部アドレス」と違ってきた場合（IP が変わった場合）は、Z4 の画面とブラウザに警告が出ます。

### 正規の証明書（Let's Encrypt）

標準の証明書は Z4 が自分で作ったもの（自己署名）です。ブラウザでは警告が出るだけで見られますが、**Google のサーバーは自己署名の証明書のサーバーに接続しません**（Apps Script で「証明書を確認しない」と指定しても接続しません。2026 年 9 月に確認）。そのため、[Google スプレッドシートのビューア](gas-viewer/README.md) で見るには正規の証明書が必要です。

1. https://www.duckdns.org に Google アカウントなどでログインし、**カメラ 1 台につき 1 つ**サブドメインを作ります（例: `mybaby-cam1`、`mybaby-cam2`）。DuckDNS の確認用の値（TXT）はサブドメインごとに 1 つなので、2 台で同じ名前を共有しないでください。
2. 各 Z4 の設定で、DuckDNS ドメイン名（`mybaby-cam1` など）とトークンを入力します。
3. 「正規の証明書を自動取得（Let's Encrypt）」をオンにします。オンにすると [Let's Encrypt の利用規約](https://letsencrypt.org/repository/) に同意したことになります。
4. 1〜2 分で、Z4 の画面とブラウザの「証明書」欄が「Let's Encrypt（YYYY/MM/DDまで）」になります。外出先 URL は `https://mybaby-cam1.duckdns.org:ポート/` になります。

しくみ:

- 確認方式は DNS（dns-01）です。Z4 が DuckDNS の API で確認用の値を設定し、Let's Encrypt がそれを確かめます。ポート 80 / 443 を開ける必要はありません（MAP-E 方式でも使えます）。
- 有効期間は 90 日で、残りが 3 分の 1（30 日）になると自動で更新します。更新のときは HTTPS サーバーが 1 秒ほど再起動します。
- 取得に失敗した場合は自己署名の証明書のまま公開を続け、1 時間後から 24 時間まで間隔を空けながら再試行します。理由は「証明書」欄に出ます。
- 証明書はドメイン名に対して発行されるので、`https://グローバルIP:ポート/` で開くと名前が合わないという警告が出ます。ドメイン名の URL を使ってください。
- アプリ内には ISRG Root X1 などのルート証明書を同梱しています（Android 7.0 以前には入っていないため）。

### 外出先から開く

スマホの**モバイル回線**（Wi-Fi をオフ）で外出先 URL（例: `https://グローバルIP:8443/`）を開きます。

アドレスは必ず `https://` から入力してください（省略すると暗号化なしで接続し、切断されます）。

正規の証明書（Let's Encrypt）を使っている場合は警告は出ません。以下は自己署名の証明書の場合です。

証明書は Z4 が自分で作ったもの（自己署名）なので、初回はブラウザに「保護されていない通信」と警告が出ます。
iPhone / Mac の条件（接続先アドレスの記載、サーバー用途の記載、有効期間 825 日以内）を満たすように作っています。有効期限の 30 日前と、外部アドレスを変えたときに自動で作り直します（そのときは指紋が変わります）。
「詳細」で表示される SHA-256 の指紋が、Z4 に表示された指紋と一致することを確かめてから進んでください。
一致しない場合は、途中で通信を横取りされている恐れがあるので、接続しないでください。

### 安全対策

- 外出先用ポートは **HTTPS（TLS 1.2 以上）だけ**で、**パスワードがないと何も返しません**。
- パスワードを 5 回間違えると、その IP からの接続を 15 分間ブロックします。
- LAN 用の HTTP ポート（8080）はパスワードなしで使えます。その代わり、家の中（プライベートアドレス）以外からの接続は拒否します。
- ルーターで開けるのは外出先用ポートだけです。外出先視聴を無効にするか、アプリを停止すると閉じます。
- 自宅のグローバル IP は、公開リポジトリのソースコードには含めていません（個人用ビルドでだけ `EXTERNAL_HOST` で埋め込めます。下記）。

### 個人用ビルド（外部アドレスを埋め込む）

```sh
EXTERNAL_HOST=203.0.113.5 APK_NAME=/安全な場所/z4motioncam-home.apk ./build-apk.sh
```

「外部アドレス」の初期値が入った APK ができます。**自宅 IP を含むので、公開リポジトリには置かないでください。**

## 制約・注意点

- **バックライトを完全に消すことはできない**: 公開 API では、タッチを受け付けたままパネルの電源を切れません。輝度 0 を指定しても、Android 側で「その機種の最低輝度」に切り上げられます。黒一色の表示と組み合わせるので、見た目はほぼ真っ暗になります。発熱への影響はごく小さいと見ています。
- **音声は録音しません**（要件外）。泣き声で通知したい場合は、音声を扱う機能を別途追加する必要があります。
- **突然の電源断では録画中のファイルが失われる**: MP4 は、動画の目次にあたる情報を録画の最後に書き込むため、録画中に電源が切れたファイルは再生できません（次の起動時に削除されます）。1 本が長いほど失う時間も長くなるので、心配な場合は「1 ファイルの最大長」を 15〜30 分にしてください。「区切らない」でも、Android の MP4 の制限（4 GB）に近づく 3.5 GB（640×480 で約 7 時間）で次のファイルに切り替えます。
- **録画開始の遅れ**: 動きを見つけてから録画が始まるまで、0.5〜1 秒ほどかかります（事前録画はしていません。処理を増やさないためです）。
- **赤外線はありません**: 真っ暗な部屋では写りません。常夜灯などの弱い明かりが必要です。
- **LAN 内の通信は暗号化されておらず、パスワードもない**: LAN 用の 8080 番は HTTP で、家の Wi-Fi につながる人は誰でも視聴・削除できます（家の外からは接続できません）。ルーターで 8080 番を手動で開放しないでください。
- **フレームレートの切り替え**: 待機中と録画中でセンサーの速度を切り替えます。切り替えに対応しないカメラドライバーの場合は、自動で固定速度に戻ります。
- **自己署名証明書（標準）**: 外出先で開くとブラウザの警告が出ます。Google スプレッドシートのビューアはつながりません。DuckDNS と「正規の証明書を自動取得」を使うと解消します（上の「正規の証明書」）。
- **外出先での視聴は通信量がかかる**: ライブ映像は 1 分あたり約 10MB（640×480・5fps の場合）です。
- **人認識は顔検出と形の判定**: 床まで届くカーテンが大きく揺れると人の形に見えることがあります（上端から下がるものと、同じ場所で揺れ続けるものは除外）。形だけの判定はペットや荷物の運搬も区別できません（上の「誤検知・見逃しの傾向」）。見逃しが困るなら動体検知を使ってください。
- **更新の導入は最後に人の操作が必要**: Z4 の画面で「インストール」を押す必要があります（サイレント導入はしません）。署名鍵が違う APK は導入できません。ブラウザから送る入口は家の Wi-Fi 内だけで、Z4 の画面に出るコードが要ります。
- **実機では未確認**: この実装は、Android 5.0 と 7.1 の API に対してコンパイルできることと、PC 上の単体テストで確認しただけです。温度の閾値は一般的なリチウムイオン電池の目安から決めたので、実機で様子を見て `ThermalPolicy` の値を調整してください。
