# Z4 MotionCam

Xperia Z4 を常時充電のまま使う、低発熱の見守りカメラアプリです。
動体を検知したときだけ録画し、同じ Wi-Fi にいるスマホや PC のブラウザから、ライブ映像と録画を見られます。

- 対象: Xperia Z4 (SO-03G / SOV31 / 402SO)。Android 5.0〜7.0 (minSdk 21 / targetSdk 25)
- 依存ライブラリなし（Android フレームワークの API だけを使用）。見る側はブラウザだけでよく、専用アプリは不要

## 要件と実装の対応

| 要件 | 実装 |
| --- | --- |
| 動体検知で録画 | プレビューの輝度を 32×24 マスに縮めて背景と比較し、2回続けて変化したら録画を開始します。動きが止まって N 秒たつと録画を止めます（`MotionDetector`, `CameraPipeline`） |
| LAN からライブ映像・録画を見る | 自前の小さな HTTP サーバーです。ライブは MJPEG、録画は Range 対応の MP4 配信で、シーク再生もできます（`HttpServer`, `assets/index.html`） |
| 充電中でも熱暴走しない | 下の「発熱対策」を参照 |
| 30 秒でバックライト OFF | 最後のタッチから 30 秒で、輝度を最低にして黒一色の画面にします。画面の更新も止めます（`MainActivity`） |
| タッチでバックライト ON | 暗い間は、どこをタッチしても元の輝度に戻ります。復帰したときのタッチでボタンが押されることはありません |
| 容量がいっぱいなら古い録画を削除 | 録画を始めるときと、録画中は 15 秒ごとに空き容量を確認します。設定値を下回ったら古いファイルから削除します（`RecordingStore`） |

## 発熱対策

既存の見守りカメラが熱暴走した原因は、常時フル稼働で処理していることだと考えています。
Z4 の SoC である Snapdragon 810 は発熱しやすいことで知られています。
そこで、必要なときだけ必要なぶんだけ処理するように作りました。

1. **カメラは低解像度・低フレームレート**: 標準は 640×480・10fps です。フレームレートの下限が低い範囲を選ぶので、暗い部屋でも無理に高感度にしません。
2. **エンコードは録画中だけ**: 監視中は動体検知しか動かしません。録画中だけハードウェアの H.264 エンコーダ（MediaCodec）を使い、ソフトウェアエンコードはしません。
3. **動体検知はとても軽い**: 1 フレームあたり約 2 万画素を読むだけです（全画素の約 6%）。これを 1 秒に 3 回まで行います。
4. **JPEG は見ている人がいるときだけ作る**: ライブ映像を見ている人がいなければ、JPEG 圧縮は一切しません。ブラウザのタブを隠すとライブは自動で止まります。見っぱなしでも 10 分で止まり、「ライブ再開」ボタンで続きを見られます。
5. **画面の描画を止める**: 暗い間はプレビューも文字も更新しません。明るい 30 秒間だけ 0.5 秒ごとに更新します。
6. **電池温度で段階的に負荷を下げる**（`ThermalPolicy`。戻るときは 2℃ のヒステリシスあり）:

   | 電池温度 | 動体検知 | ライブ | 録画 fps |
   | --- | --- | --- | --- |
   | 39℃ 未満 | 3 回/秒 | 5 fps | 設定値 |
   | 39℃ 以上 | 2 回/秒 | 2 fps | 最大 8 |
   | 42℃ 以上 | 1 回/秒 | 1 fps | 最大 5 |
   | 45℃ 以上 | **カメラを一旦解放して冷却を待ちます**（43℃ を下回ると自動で再開。録画中のファイルは正しく閉じます） |

   45℃ で止める理由: 端末が熱で強制終了すると、その後は何も記録できません。短時間止めて冷ますほうが、失う時間が少なく済みます。

7. **再起動からの復帰**: 端末が起動すると自動で監視を再開します（設定でオフにできます）。

### 端末側でやっておくと効果が大きいこと

- **急速充電器（Quick Charge）を使わない**: 5V/1A 程度の普通の充電器にします。充電による発熱が大きく減ると考えられます。
- **いたわり充電（Battery Care）をオンにする**: Android 6 以降の Xperia にある機能です。満充電のまま充電し続ける時間を減らせます。
- ケースを外し、放熱しやすい向き（背面を浮かせる）で設置します。直射日光と布団の上は避けてください。
- 画面ロックを「なし」にします。停電などで再起動したとき、ロック解除なしで監視を再開するためです。
- 自動アップデートと不要なアプリを止め、裏で動く処理を減らします。

## ダウンロード（ビルド済み APK）

Z4 のブラウザで次の URL を開くとダウンロードできます。

https://github.com/fallere304-sys/anything-llm/raw/claude/xperia-z4-motion-camera-7x4wet/xperia-z4-motion-camera/release/z4motioncam-1.0.apk

1. 「設定 > セキュリティ > 提供元不明のアプリ」をオンにします。
2. ダウンロードした APK を開いてインストールします。

注意: このAPKは開発環境で作った署名鍵で署名しています。**別の鍵で署名されたAPKでは上書き更新できません。** その場合は一度アンインストールが必要で、アンインストールすると保存済みの録画（`Android/data/com.z4motioncam/`）も消えます。更新するときは先に録画を退避してください。

## ビルドとインストール

Android Studio（JDK 17 以上）でこのフォルダ `xperia-z4-motion-camera/` を開き、そのままビルドします。

```sh
cd xperia-z4-motion-camera
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`./gradlew test` で PC 上の単体テストを実行できます。対象は動体検知、温度制御、ストレージ削除、HTTP（Range と認証）、色変換です。

Z4 に入れるには、「設定 > セキュリティ > 提供元不明のアプリ」を許可してから APK を入れてください。

Android Studio を使わずに作る場合は、Ubuntu のパッケージ（`aapt` `apksigner` `zipalign` `dalvik-exchange` `android-sdk-platform-23`）を入れて `./build-apk.sh` を実行します。`release/` に署名済み APK ができます。

## 使い方

1. アプリを起動し、カメラの権限を許可します。
2. 画面左上に `http://192.168.x.x:8080/` が出るので、同じ Wi-Fi のスマホや PC のブラウザで開きます。
   - 上がライブ映像、下が録画一覧です。タップで再生、「保存」でダウンロードできます。
   - 状態、電池温度、空き容量、最後に動きを検知した時刻も表示されます。
3. 30 秒たつと画面が暗くなります。タッチすると 30 秒間だけ元に戻ります。
4. 「停止」ボタンで監視を終了します。

### 設定（画面の「設定」ボタン）

| 項目 | 標準値 | 説明 |
| --- | --- | --- |
| 解像度 | 640×480 | 1280×720 にもできますが、発熱は増えます |
| フレームレート | 10 fps | 5 fps にすると最も発熱が少なくなります |
| 映像の回転 | 0° | 設置の向きに合わせます（録画とライブの両方に反映） |
| 検知感度 | 中 | 「高」は寝返りのような小さな動き向け。誤検知が多ければ「低」にします |
| 録画を続ける秒数 | 10 秒 | 動きが止まってから録画を止めるまでの時間 |
| 1 ファイルの最大長 | 5 分 | 動きが続くときは、この長さでファイルを分けます |
| SD カードを優先 | オン | microSD があればそこに保存します |
| 確保する空き容量 | 500 MB | これを下回ると、古い録画から削除します |
| ポート番号 | 8080 | |
| 閲覧パスワード | （なし） | 設定すると、ブラウザでパスワード入力が必要になります（ユーザー名は何でも可） |
| 起動時に自動で開始 | オン | |

録画は `Android/data/com.z4motioncam/files/Movies/recordings/`（SD カードまたは内部ストレージ）に `yyyyMMdd_HHmmss.mp4` という名前で保存されます。

## 構成

```
MainActivity     画面（プレビューと状態表示、30 秒で減光、タッチで復帰）
CameraService    フォアグラウンドサービス（カメラ、HTTP、電池温度の監視、WakeLock）
 ├─ CameraPipeline   Camera1 のプレビューコールバックを受け、1 本のスレッドで検知・録画・JPEG 生成
 │   ├─ MotionDetector   輝度グリッドの背景差分（中央値で明るさ補正、2 回連続で確定）
 │   ├─ VideoRecorder    NV21 → NV12/I420 変換 → MediaCodec (H.264) → MediaMuxer (MP4)
 │   └─ PreviewSink      画面に出さない 1×1 の EGL サーフェス（プレビューの受け皿）
 ├─ RecordingStore   保存先、空き容量の確保、古い録画の削除
 ├─ FrameHub         最新の JPEG を見る人に渡す（見る人がいるときだけ生成）
 ├─ HttpServer       / , /stream.mjpg , /snapshot.jpg , /api/status , /api/recordings , /rec/<name>
 └─ ThermalPolicy    電池温度 → 負荷レベル
```

## 制約・注意点

- **バックライトを完全に消すことはできない**: 公開 API では、タッチを受け付けたままパネルの電源を切れません。輝度 0 を指定しても、Android 側で「その機種の最低輝度」に切り上げられます。黒一色の表示と組み合わせるので、見た目はほぼ真っ暗になります。発熱への影響はごく小さいと見ています。
- **音声は録音しません**（要件外）。泣き声で通知したい場合は、音声を扱う機能を別途追加する必要があります。
- **録画開始の遅れ**: 動きを見つけてから録画が始まるまで、0.5〜1 秒ほどかかります（事前録画はしていません。処理を増やさないためです）。
- **赤外線はありません**: 真っ暗な部屋では写りません。常夜灯などの弱い明かりが必要です。
- **通信は暗号化されていない**: HTTP のみです。パスワードも平文で流れるので、家庭内 LAN 専用として使ってください（ルーターでポート開放しないこと）。
- **実機では未確認**: この実装は、Android 5.0 と 7.1 の API に対してコンパイルできることと、PC 上の単体テストで確認しただけです。温度の閾値は一般的なリチウムイオン電池の目安から決めたので、実機で様子を見て `ThermalPolicy` の値を調整してください。
