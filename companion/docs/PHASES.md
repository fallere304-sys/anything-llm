## Phase 8(先行): 知識・処理アクセスの可視化画面 — 完了(2026-10-02)
ユーザー提供の参考画像(赤いネットワーク・ガラス球ノード・緑のチップ核・シアンのHUD円弧)に合わせて先行実装。

### 実装
- バックエンド: `buddy/activity.py`。ノード定義(実装済み/未実装を正直に返す)と `activity` イベント(start / end / pulse)
- チャット処理が「実際に行ったアクセス」を発行: 人格の適用、会話履歴の参照件数、LLMへの問い合わせ開始/終了(所要時間・文字数)。要約に会話本文は含めない
- フロント: `static/viz.js`(Canvas 2D、依存なし)
  - 核の光り方が状態で変わる(待機 / 考え中=黄 / 応答中 / エラー=赤)
  - 要求は核→ノード(黄の粒子)、応答はノード→核(シアンの粒子)
  - 未実装ノード(記憶・PJ・Web・File・Tool)は暗い点線で、光らない
- 処理ログ(時刻・対象・要約)、ノードをタップすると詳細表示、可視化の表示切替
- PC は左に可視化・右に会話、スマホは上に可視化・下に会話
- 待機中は描画を約20fpsに間引く。OSの「視差効果を減らす」設定では粒子・揺れを止める
- UI を `index.html` / `style.css` / `app.js` / `viz.js` に分割(`/static` 配信)

### テスト
- pytest 48件成功(アクセスイベントの順序・対応関係、本文を含まないこと、失敗時に ok=false で終了、ノードの可否)
- ヘッドレスChromium(390px / 1366px)で表示・処理ログ・ノード詳細・表示切替を確認。コンソールエラー無し

### 問題点・未検証
- 実スマホでの描画負荷(発光表現の `shadowBlur` は低性能端末で重い可能性)
- 音声出力のアクセスはブラウザ側で記録(サーバーの処理ログには残らない)
- 作業履歴(永続化された処理ログ)は未実装(Phase 3)
