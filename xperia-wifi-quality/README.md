# Wi-Fi電波品質（Xperia Z4 向け）

周囲の Wi-Fi 電波をすべて一覧表示し、推定通信品質を算出する Android アプリ。

- 10 秒ごとに再スキャンして更新
- 検知したすべての電波（BSSID 単位）を表示し、電波の強い順（RSSI 降順）に並べる
- 各行の表示: SSID / ch（バンド・チャネル幅・BSSID）/ 電波強度の横棒グラフ（dBm）/ 推定通信品質 %
- 接続中の AP には ★ を表示
- 計測中は画面を消灯させない

APK: [`dist/WifiQuality.apk`](dist/WifiQuality.apk)（v1.1、minSdk 21 = Android 5.0、targetSdk 23）

## インストール

1. APK を端末にコピーする
2. 「設定 → セキュリティ → 提供元不明のアプリ」を許可する
3. APK をタップしてインストールする
4. Android 6.0 以降では、初回起動時に位置情報の権限を「許可」し、位置情報（GPS）をオンにする。
   Android の仕様上、この 2 つがないとスキャン結果を取得できない。

## 推定通信品質の計算

`推定品質 = 信号係数 × 混線係数 × 100`（至近距離・混線なしのとき 100%）

**信号係数**: IEEE 802.11n/ac の受信最小感度（20MHz）で、その RSSI で使える MCS の
伝送レートを MCS9 (86.7Mbps) で割った値。区間は線形補間する。
チャネル幅が 2 倍になるごとに必要な感度は 3dB 上げる。

| RSSI (20MHz) | -57 | -59 | -64 | -66 | -70 | -74 | -77 | -79 | -82 | -90 |
|---|---|---|---|---|---|---|---|---|---|---|
| 信号係数 | 100% | 90% | 75% | 60% | 45% | 30% | 22.5% | 15% | 7.5% | 0% |

**混線係数**: 無線LAN（CSMA/CA）では、他の電波がチャネルを使っている間は送信を待たされる。そこで「チャネルが空いている時間の割合」を混線係数とする。

```
混線係数 = (1 − Up) × (1 − Us × (1 − 20/W))
  Up: 自分のプライマリ 20MHz が他の電波で使われている時間の割合（この間は送信できない）
  Us: 40/80/160MHz 時の残りの帯域が使われている時間の割合（この間は 20MHz に縮退する）
  W : 自分のチャネル幅 [MHz]
```

以前の版では係数 0.5（他の電波の送信時間率を仮定した値）を使っていたが、1.1 で廃止した。
約1万台の AP を実測した研究で「チャネル上のネットワーク数は使用率を予測しない」と報告されているため、
電波の数に係数を掛ける考え方自体をやめた。代わりに、以下の根拠のある値を上から優先して使う。

| 優先 | Up / Us の求め方 | 根拠 |
|---|---|---|
| 1 | AP がビーコンで報告する **BSS Load 要素**の Channel Utilization（対象 AP の値。無ければ同じ ch で最も強い AP の値） | IEEE 802.11 の BSS Load 要素（Element ID 11）。「AP が媒体をビジーと検知した時間の割合 ×255」と定義された実測値 |
| 2 | 送信を待たされる電波が 1 つ以上あるとき、`max(ビーコン占有率の合計, バンドの典型使用率)` | 下記 |
| – | 送信を待たされる電波が無い | 0 |

- **送信を待たされるかの判定**（IEEE 802.11 OFDM PHY の CCA 要件）
  - 自分のプライマリ ch で相手のプリアンブルを復調できる場合（同じ ch、または相手の 40/80MHz チャネルの一部）: 受信電力が **-82dBm 以上**
  - 復調できない部分的な重なり（2.4GHz の隣接 ch など）: 帯域内エネルギー `RSSI + 10log10(重なり幅/相手の占有幅)` が **-62dBm 以上**
- **ビーコン占有率** = フレーム時間 / ビーコン間隔 100TU (102.4ms)
  - DSSS 1Mbps: `192µs + 8L/rate`。OFDM: `20µs + 4µs × ceil((16+8L+6)/(4×rate))`（2.4GHz は信号拡張 +6µs）
  - L（フレーム長）とレートは、情報要素を取得できればその値を使う。取得できないときは 200 byte（WPA2/11n AP の最小構成から計算した値）、2.4GHz は 1Mbps、5GHz は 6Mbps とする
  - 例: 2.4GHz 1Mbps のビーコン 1 つで 1.75%。同じ ch に 15 個あると 26%（典型値の 20% を超えるため、こちらを採用）
- **典型使用率**: Biswas et al., "Large-scale Measurements of Wireless Network Behavior", ACM SIGCOMM 2015（Meraki の AP 約1万台の実測）
  - 2.4GHz: 大半の AP で 20% 以上（上位 10% では 50% 超）→ 下限値の **20%**
  - 5GHz: 平均 **2%**

**実測値（BSS Load）を取得できる OS**: AOSP 系のソースで確認した。
- **Android 7.x**: wpa_supplicant から受け取った情報要素が、ScanResult の非公開フィールドに入る。アプリはこれを読める（Android 8 以前は非公開 API の制限が無い）
- **Android 5.x / 6.x**: 情報要素がアプリまで渡されないため、推定値になる
- Z4 を Android 7 に更新し、かつ AP が BSS Load を送信している場合（業務用 AP に多い）は、画面に「AP実測」と表示される

画面の各行には、混線の度合い、同じ ch の電波数、部分的に重なる電波数、副 ch の電波数、ch 使用率（AP実測／推定）、信号係数 × 混線係数を表示する。

> 注意: 推定値に反映されないもの
> - 送信を待たされない程度に弱い電波が、雑音として SN 比を下げる影響
> - 隠れ端末（自分には聞こえない端末）の影響
> - 端末性能、MIMO の本数
>
> 典型使用率は米国の業務用ネットワークの統計なので、日本の住宅環境とは差がありうる。
> また AP の実測値には、その AP 自身の通信も含まれる。
> Android 5.x ではチャネル幅を取得できないため、すべて 20MHz として計算する（画面には「幅不明」と表示）。

## ビルド

Gradle は使わず、Ubuntu の Android SDK パッケージでビルドする。

```sh
sudo apt-get install aapt apksigner zipalign android-sdk-platform-23 dalvik-exchange
./build.sh                                        # → dist/WifiQuality.apk
java -cp <classes> QualityEstimatorTest          # 推定ロジックのテスト（test/）
```

署名鍵は初回ビルド時に `keystore/` へ自動生成する（git には含めない）。
別の鍵でビルドした APK を上書きインストールすることはできないので、その場合は一度アンインストールしてから入れ直す。
